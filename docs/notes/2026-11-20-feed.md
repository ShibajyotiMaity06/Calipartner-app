# Feed release and operations

Home opens the existing Log sheet from the unboxed + Log action beside the menu. The centre globe opens Feed. A post contains one photo or video up to 10 MB, a media description and an optional caption. Friends is the default audience. Community follows social profile visibility and discoverability. Feed shares appear under Shared with you and follow current friendships, squad membership and the original post audience. External links require sign-in and the same access.

Compare uses each person's goal-completion percentage for the calendar date stored on the post, using their own tracking time zone. The author opts in per post. The server checks the viewer's current Plus or Pro entitlement. The Free viewer opens the existing paywall. The app receives only percentages, with unavailable values shown through a lock and text.

## Deployment

1. Apply [the Feed migration](../../supabase/migrations/20261120000100_social_feed.sql), then deploy `feed-api` and `delete-account` to the linked Supabase project. Publish the app via the existing web and native release workflows.
2. Use the existing private R2 chat bucket and signing secrets for the `feed/` object prefix. The existing moderation configuration is used for photos and text. Video moderation requires the existing Gemini secret. Publish requires a successful check before the post is visible.
3. Verify with a private account and a second eligible viewer. Upload a supported photo and short video, test a new comment, open a signed-in link, verify the Free paywall, then delete the test posts. Confirm access revocation when the poster changes profile visibility or blocks the viewer. Signed media URLs expire after five minutes.

## Moderation

Feed requires explicit acceptance of its guidelines for posting and commenting. Report options cover posts, comments and people. Post and comment reports are recorded in `feed_reports`. User reports go to the existing `reports` queue. Block uses the existing account block controls. CaliPartner support contact is published in the app terms and on the support page.

Assign a reviewer to check both report queues and respond to reports. Authorized operators can call `resolve_feed_report` with the report ID and the removal decision. When it returns a storage key, remove that private object from R2. Limit this access to the moderation team. Recheck the terms and privacy disclosures when release scope changes.
